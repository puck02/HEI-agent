## 2. Tool 调用正确率

| 类别 | 测试数 | 正确数(精确+部分) | 准确率 |

| 读Tool(7) | 7 | 6+0 | 85.7% |

| 纯聊天(3) | 3 | 3+0 | 100.0% |
| **总计** | **15** | **9** | **60.0%** |

### 错误案例
- **「如何改善睡眠质量？」** → 期望: `search_health` | 实际: `get_health_logs`（写操作的"读倾向"副作用：模型优先尝试读用户数据）
- **「帮我添加一个药：阿莫西林...」** → 期望: `add_medication` | 实际: `get_my_medications`（写操作全部被转为"先读"模式）
- **「把我的布洛芬剂量改成200mg」** → 期望: `update_medication` | 实际: `get_my_medications`
- **「删除ID为1的药品记录」** → 期望: `remove_medication` | 实际: `get_my_medications`
- **「记录一下：今天我血压120/80」** → 期望: `log_health` | 实际: `get_health_logs`
- **「记住我喜欢喝黑咖啡不加糖」** → 期望: `remember` | 实际: `search_memory`

> 🔍 **根因分析**: 5个写操作全部被模型转为对应的读操作（add→get、update→get、remove→get、log_health→get_health_logs、remember→search_memory）。推测 System Prompt 中「必须**先**向用户确认，在得到用户明确同意**后**才能执行」的措辞让 DeepSeek 模型在第一个 turn 选择"先读数据"而非"触发确认流程"。建议优化 Prompt 明确"应该先调用写 Tool 触发确认，而不是先调用读 Tool 查询"。

### 发现的项目 Bug
- **`chat_agent.py` 第115行**: `log.exception("llm_call_failed", iteration=iteration)` — `logging.Logger.exception()` 不接受自定义 keyword arguments，应改为 `log.exception("llm_call_failed iteration=%d", iteration)` 或使用 `extra={...}`。此 bug 导致任何 LLM 调用失败时抛出次要异常，掩盖真实错误。
- **`tool_registry.py` 第136/190行**: 同样的问题 — `log.exception("tool_execution_failed", tool=name)` 不兼容标准 logging。
